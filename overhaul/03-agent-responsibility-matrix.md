# 03 — Agent Responsibility Matrix

## General ownership

**Claude Code owns:** product/architecture interpretation of the audit, the task registry and dependency graph, design-system contracts (token/component APIs, not their migration), the booking/security/data-integrity risk models, Arabic/RTL architecture rules, the landing-page direction, documentation and decision logs, final integration review, and merge-order decisions.

**Codex owns:** implementation inside bounded worktrees, mechanical/repetitive fixes (broken links, dead buttons, i18n wiring against an existing DICT), test authoring against Claude-specified acceptance criteria, responsive/accessibility fixes, browser-based visual verification once the Playwright MCP exists, dependency-upgrade execution, and image-asset production via `image_gen`.

**Never:** both agents independently redesigning the same surface. Every task in `tasks.json` has exactly one implementing owner and, where risk warrants it, exactly one reviewer.

## Execution-type legend (used throughout `tasks.json`)

| Type | Meaning |
|---|---|
| **A** | Claude-led architecture/decision task. No implementation, or trivial implementation Claude does directly (e.g., editing `CLAUDE.md`). |
| **B** | Codex-led implementation task. Bounded, mechanical, low ambiguity. Claude reviews the diff, doesn't co-design it. |
| **C** | Claude writes the spec/contract; Codex implements against it. Claude reviews for spec fidelity. |
| **D** | Codex runs discovery (crawl, scan, profile); Claude makes the resulting decision. |
| **E** | High-risk paired task (payments, auth, data integrity, DB migration, deletion). Claude defines risk model + acceptance criteria before any code is written; Codex implements in isolation; Claude reviews diff + test evidence; a second validation pass occurs before merge; rollback is documented. |
