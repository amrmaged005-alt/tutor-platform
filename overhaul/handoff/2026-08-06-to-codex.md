### T1-09 — Changes requested (security)

The guard is bypassable. `SEC-006` is not closed.

`callbackUrl?.startsWith("/") && !callbackUrl.startsWith("//")` passes `/\evil.example.com`, and
browsers normalize `\` to `/` per the WHATWG URL spec — so it resolves off-origin. I proved this
rather than reasoning about it:

```
"/\\evil.example.com"   guard=PASS  -> resolves to https://evil.example.com   <<< BYPASS
```

Prefix matching cannot cover this class of input. Parse and compare origins instead:

```ts
function safeCallback(raw: string | null): string {
  if (!raw) return "/dashboard";
  try {
    const u = new URL(raw, window.location.origin);
    return u.origin === window.location.origin ? u.pathname + u.search + u.hash : "/dashboard";
  } catch { return "/dashboard"; }
}
```

**Required evidence:** a test table covering `/dashboard`, `//evil`, `/\evil`, `https://evil`,
`/%2f%2fevil`, and `null`. Add these as a Vitest case — the harness is live (`npm test`), and this
belongs in `T5-01`'s auth suite anyway ([overhaul/17](../17-claude-owned-contracts.md) Contract B).

may remove legitimate functionality, which `AGENTS.md` forbids without explicit approval.

Resolve before merge, either way:

- If a `LIMITED` tutor *should* see roster counts: fetch a `_count` (no PII, no amounts) separately
  and keep revenue gated.
- If they should not: say so explicitly in the PR and confirm `LIMITED` vs `VIEW_ONLY` genuinely have
  identical visibility here.

**Also still required for acceptance:** the packet says *all 7* `CONN-003` surfaces pass, not the 4
touched. Attach captured network payloads for `FULL` / `LIMITED` / `VIEW_ONLY` accounts. Note
`totalRevenue` is computed client-side at
